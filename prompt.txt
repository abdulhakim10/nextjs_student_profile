# Complete Frontend Implementation Guide - Attendance Admin (All Settings)

## Introduction

This guide provides **everything** needed to build the frontend for the **full Attendance Admin module**: Day Type, Working Policy, Ruleset, Schedule Template, Attendance Group, and Employee Profile. It follows the same detailed format as the [Attendance Settings Frontend Guide](./FRONTEND_IMPLEMENTATION_GUIDE.md) (location/device) and aligns with the [Admin Setup documentation](./admin_setup.mdx).

**Base URL:** `http://your-api.com/{app}/{user}`  
**Required Headers (all requests):**
```javascript
{
  "x-encrypted-key": "your_encrypted_key",
  "x-encrypted-user": "your_encrypted_user",
  "Content-Type": "application/json"
}
```

## Setup Flow & Dependency Order

Configuration **must** follow this order (backend may auto-create some; see flows below):

```
1. Day Type (standalone)
2. Working Policy (standalone)
3. Ruleset (standalone)
4. Schedule Template (standalone)
5. Attendance Group (uses: Schedule + Ruleset + optional Day Type + OT Policy)
6. Employee Profile (uses: Attendance Group; can override OT)
```

**Quick path:** You can create an **Attendance Group** first with only `sid`, `name`, `level`, `description`. The backend will auto-create a default Schedule Template and Ruleset for that org if they don’t exist. For full control, create Schedule and Ruleset (and optionally Day Type + Working Policy) first, then create the group.

## 1. Day Type

**Purpose:** Define day categories (e.g. working day, rest day, public holiday) with flags: paid, overtime allowed, etc.  
**Collection:** `attendance_day_types`

### 1.1 Create Day Type

**Endpoint:** `POST /admin/settings/day-type`

**Request Body:**
```json
{
  "sid": "0",
  "level": "0",
  "description": "Sunday and Saturday",
  "name": "Working day",
  "isWorkingDay": true,
  "isPaid": true,
  "allowOvertime": true,
  "isActive": true
}
```

**Success Response (200):**
```json
{
  "success": true,
  "message": "Setting day type created successfully",
  "data": {
    "code": "DAYTYPE-FBAF72B2"
  }
}
```

## Complete User Flows (Frontend)

### Flow A: Full Setup (Step-by-Step)

**Goal:** Configure from scratch in dependency order.

```
Step 1: Create Day Type(s)
  POST /admin/settings/day-type
  Body: { sid, name, description, isWorkingDay, isPaid, allowOvertime, isActive }
  → Save returned "code" (e.g. DAYTYPE-XXX)

Step 2: Create Working Policy (OT)
  POST /admin/settings/working-policy
  Body: { name, description, isActive, allowed, rules }
  → Save "code" (e.g. OT-XXX)

Step 3: Create Ruleset
  POST /admin/settings/ruleset
  Body: { sid, name, description, flexible, flexWindowActive, flexWindow?, maxPair, doublePunchInSeconds, isActive }
  → Save "code" (e.g. RULE-XXX)

Step 4: Create Schedule Template
  POST /admin/schedule
  Body: { sid, name, description, isActive, schedule: { "0".."6": DaySchedule } }
  → Save "code" (e.g. SCHE-XXX)

Step 5: Create Attendance Group
  POST /admin/group
  Body: {
    sid, name, level, description,
    rulesetCode: "RULE-XXX",
    scheduleTemplateCode: "SCHE-XXX",
    dayTypeCode: "DAYTYPE-XXX" (optional),
    otPolicyCode: "OT-XXX" (optional)
  }
  → Save "groupCode" (e.g. ATTGRP-XXX)

Step 6: Assign Employee to Group
  PUT /admin/settings/employee-attendance-profile
  Body: { uid, sid, attendance_group_code: "ATTGRP-XXX", ot_policy_code: "OT-XXX" (optional) }
```

**UI suggestion:** Wizard with 6 steps; each step shows form + “Next” / “Back”. Final step shows summary and “Complete Setup”.

---

### Flow B: Quick Create (Group First)

**Goal:** Let backend auto-create Schedule + Ruleset.

```
Step 1: Create Group (minimal)
  POST /admin/group
  Body: { sid: "1", name: "Default Group", level: "0", description: "" }
  → Backend creates default Schedule Template + Ruleset if missing
  → Response: groupCode, scheduleTemplateCode, rulesetCode

Step 2: (Optional) Edit schedule/ruleset
  GET /admin/schedule?code=<scheduleTemplateCode>
  PUT /admin/schedule with desired weekly schedule

  GET /admin/settings/ruleset?sid=1
  PUT /admin/settings/ruleset with desired ruleset code and fields

Step 3: Assign employees
  PUT /admin/settings/employee-attendance-profile
  Body: { uid, sid, attendance_group_code: "<groupCode>" }
```

**UI suggestion:** “Quick setup” button → single form (org + group name) → then “Edit schedule” / “Edit rules” links to full editors.

---

### Flow C: Edit Existing Group

**Goal:** Change schedule, ruleset, or OT policy for a group.

```
Step 1: Get group
  GET /admin/group?code=ATTGRP-XXX

Step 2: Update group
  PUT /admin/group
  Body: { code, sid, name, level, description, rulesetCode, scheduleTemplateCode, dayTypeCode?, otPolicyCode?, isActive }

  (To change schedule hours: GET/PUT /admin/schedule for scheduleTemplateCode)
  (To change rules: GET/PUT /admin/settings/ruleset for rulesetCode)
```

---

### Flow D: Assign / Reassign Employee

**Goal:** Set or change an employee’s group and optional OT override.

```
Step 1: Get list of groups
  GET /admin/group/list?sid=1

Step 2: (Optional) Get list of OT policies
  GET /admin/settings/working-policy?sid=1

Step 3: Create or update profile
  PUT /admin/settings/employee-attendance-profile
  Body: {
    uid: "user123",
    sid: "1",
    attendance_group_code: "ATTGRP-XXX",
    ot_policy_code: "OT-XXX"  // optional override
  }
```

**UI suggestion:** Employee search/select → dropdown “Attendance group” → optional “OT policy override” → Save.

## UI/UX Recommendations

### 1. Left Menu / Tabs (by entity)

- Day Types  
- Working Policies (OT)  
- Rulesets  
- Schedule Templates  
- Attendance Groups  
- Employee Profiles  

Each section: list view + “Add” → form (create/edit) with fields as in request bodies above.

### 2. Schedule Template UI

- **Weekly grid:** 7 rows (Sun–Sat); columns: Enabled, Clock In, Clock Out, Break In, Break Out, Day Type (dropdown), Override (checkbox); if Override, show Ruleset + OT Policy dropdowns.
- **Time inputs:** Use time pickers; send as "8.00" or "08:00" etc. per backend expectation.
- **Night shift:** If clockOut < clockIn, backend will set `shift_span: 2`; show a short note in UI.

### 3. Attendance Group form

- **Dropdowns:** Schedule Template (from list), Ruleset (from list), Day Type (optional), OT Policy (optional).
- **Quick create:** If “Create default schedule/ruleset” is chosen, call only POST group with minimal body and show success with created codes.

### 4. Employee Profile

- **List:** Table with uid, sid, group name, OT override (if any), actions (View, Edit, Delete).
- **Detail:** GET by uid+sid; show group name, schedule summary, and override section (OT policy dropdown, flexible checkbox if applicable).
- **Edit:** Same as “Update” body; ensure group and OT (if filled) exist before submit.

### 5. Validation (frontend)

- **Day type:** Required name, at least one of isWorkingDay/isPaid/allowOvertime meaningful.
- **Working policy:** `rules.min_minutes`, `rounding_minutes`, `max_daily_hours` present and valid.
- **Ruleset:** If flexWindowActive then flexWindow (earliestIn, latestIn, requiredHours) required; maxPair ≥ 1; doublePunchInSeconds ≥ 0.
- **Schedule:** Keys "0"–"6" all present; if enabled, clockIn/clockOut format valid.
- **Group:** scheduleTemplateCode and rulesetCode required when not using “quick create”; optional codes must exist if provided.
- **Employee profile:** attendance_group_code required; user (uid) and group must exist (backend will reject otherwise).

## Error Handling (Common)

- **404 “Day type not found”** (update/delete): Refresh list; show “No longer exists”.
- **404 “Working policy not found”**: Same.
- **404 “Attendance ruleset not found”**: Same.
- **404 “Schedule template not found”**: Same.
- **404 “Attendance group not found”**: Same.
- **404 “User not found”** (employee profile): Check uid/sid; show “Invalid employee”.
- **404 “Attendance group not found”** (profile): Group was deleted; ask user to pick another group.
- **400 “Device code already exists”**: Only for device API; for admin settings, any 400: show message, highlight invalid fields.

Always surface backend `message` in a toast or inline error.
